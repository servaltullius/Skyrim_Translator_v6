# LOTD 원문으로 Gemini·Solar 번역 비교해봄 — 무료 웹 1차 테스트

스카이림 번역기에서 쓸 모델을 고르려고 LOTD 실제 영문으로 비교를 돌려봤음.

이번에 확보한 결과만 보면 **품질 우선은 Gemini 3.8 Flash 유지, 비용을 줄일 후보는 3.1 Flash Lite** 쪽으로 생각 중임. Solar는 이번 무료 웹 테스트에서 미번역과 문맥 오류가 꽤 보였음.

먼저 조건부터 밝히면, **실행과 1차 의미 검토는 Codex를 이용했음. 사람이 모델명을 가리고 채점한 결과는 아님.** 특히 Solar Pro 4는 Solar Chat이라는 웹 서비스 경로로 실행돼서, 이걸 그대로 Pro 4 API 성능이라고 보면 안 됨.

## 어떻게 비교했나

합성 문장을 새로 만든 게 아니라 LOTD 영문 XML에서 120개를 고정 추출했음.

- 대사 50개 / 책 20개 / 퀘스트 20개 / 아이템·UI 30개
- 먼저 그중 24개를 Gemini 두 모델과 Solar 두 경로에 넣었음.
- 이후 Gemini 두 모델은 긴 책까지 포함한 120개로 확대했음. 가장 긴 책 원문은 약 1만 2천 자였음.
- 각 요청은 새 대화에서 시작했고, 원문·확인 가능한 문맥·용어집·번역 지시는 동일하게 줬음.
- NPC 화자나 상대 관계를 XML에서 확인할 수 없는 경우에는 모른다고 표시했음.
- 결과는 고치기 전 응답 그대로 저장했음. 기존 한국어 번역을 정답으로 주지는 않았음.

실행 경로와 설정은 아래와 같음.

| 모델 | 실행 경로 | 추론 설정 |
| --- | --- | --- |
| Gemini 3.8 Flash | Google AI Studio | Low |
| Gemini 3.1 Flash Lite | Google AI Studio | Minimal |
| Solar Pro 3 | Upstage Playground | Low |
| Solar Pro 4 | Solar Chat | 즉시 |

입력은 같아도 추론 수준·기본 설정·웹 서비스 내부 처리가 모두 같은 실험은 아님. Gemini는 API 키와 검색 등의 도구를 선택하지 않았고, Solar Pro 3는 temperature 0.8에 빈 시스템 프롬프트를 사용했음.

추가 결제나 유료 API 직접 호출 없이 실행했고, 앱의 태그 보호·후처리를 거치기 전 결과를 비교한 것임.

## 실제 번역에서 보인 차이

### 1. Red Year가 일출로 바뀌는 경우

원문: **What about before the Red Year?**

| 모델 | 실제 출력 |
| --- | --- |
| 3.8 Flash | 붉은 해 이전에는 어땠나요? |
| 3.1 Flash Lite | 붉은 해가 오기 전은 어땠나요? |
| Solar Pro 3 | 붉은 해 이전은 어땠어? |
| Solar Pro 4 웹 | 붉은 해가 뜨기 전에는 어땠어요? |

마지막은 Red Year라는 사건을 해가 뜨는 상황으로 읽어버렸음. 이런 건 JSON이나 태그 검사만으로는 못 잡음.

### 2. 용어집을 줘도 안 지킬 수 있음

다른 일지에 **7th of Sun's Dawn**이 나왔고, 용어집에 **Sun's Dawn = 2월**을 명시했음.

| 모델 | 실제 출력 |
| --- | --- |
| 3.8 Flash | 2월 7일 |
| 3.1 Flash Lite | 태양의 달 7일 |
| Solar Pro 3 | 2월 7일 |
| Solar Pro 4 웹 | 선성의 여명 7일 |

이 표본에서는 3.8과 Solar Pro 3가 지정값을 지켰고, 나머지 둘은 다른 표현을 만들었음. Lite도 용어 검사는 필요한 이유임.

### 3. 자연스러운 대사에서는 이런 차이가 났음

원문: **Ah, I'm glad I caught you, I have something for you.**

| 모델 | 실제 출력 |
| --- | --- |
| 3.8 Flash | 아, 마침 잘 만났군. 자네에게 줄 게 있네. |
| 3.1 Flash Lite | 아, 당신을 만나서 다행이군요. 드릴 게 있습니다. |
| Solar Pro 3 | 아, 너를 만나서 반가워, 너에게 줄 게 있어. |
| Solar Pro 4 웹 | 아, 잘 만났네요. 당신에게 드릴 게 있어요. |

이 문장처럼 네 출력 모두 이해 가능한 경우도 있었음. 3.8의 표현이 게임 대사로 자연스럽게 읽히지만, 실제 화자 관계를 모르므로 반말/존댓말 자체를 정답으로 채점하지는 않았음.

### 4. 책에서는 미번역과 출력 구조도 문제였음

Solar Pro 3는 계약서 한 건을 **영어 원문 그대로** 반환했음. 다른 책에서는 제목·부제·저자 행을 영어로 남겼고, 아이템·퀘스트 6개를 묶은 요청은 닫히지 않은 JSON을 네 번 반복했음.

Solar Pro 4 웹은 한 책의 본문 대부분을 영어로 남기면서 장식 이미지 태그를 지웠음. `riches가`, `런estone`처럼 한글과 영어가 섞인 결과도 있었음.

다만 Pro 4 웹은 내부 작업 단계를 거치는 서비스라, 기반 모델 문제인지 웹 서비스 처리 문제인지는 이번 실험으로 구분할 수 없음.

## 120개로 늘렸을 때의 안정성

여기서 JSON은 번역기가 결과를 읽기 위한 출력 구조이고, 형식 검사는 태그·변수·줄바꿈 등이 보존됐는지를 보는 것임.

| 항목 | Gemini 3.8 Flash | Gemini 3.1 Flash Lite |
| --- | ---: | ---: |
| 비교 대상으로 잡은 원문 | 120개 | 120개 |
| 응답을 확보한 원문 수 | 116개 | 119개 |
| 그중 JSON 구조 검사 통과 | 116개 | 116개 |
| 그중 태그·줄바꿈 등 형식 검사 통과 | 114개 | 112개 |

**이 표는 번역 정확도 점수가 아님.** 영어 원문을 그대로 복사한 응답도 형식은 통과할 수 있음. 의미 검토는 앞의 24개를 중심으로 했고, 120개 전체를 사람이 채점한 것은 아님.

3.8은 마지막 퀘스트 4개 요청에서 무료 이용 한도에 걸렸음. 확보한 응답 중 JSON 구조 실패는 없었지만 책 2개에서 줄바꿈 손실이 있었음.

3.1은 계약서 1개가 서버 오류로 두 번 실패했음. 응답을 확보한 장문 요청 중 3개는 불필요한 최상위 키를 붙이거나 중괄호를 잘못 닫았고, JSON을 읽을 수 있는 결과 중에서도 책 4개에 줄바꿈 손실이 있었음.

예비 비교와 입력이 완전히 같은 요청은 재사용했음(3.8은 5개 요청, 3.1은 4개 요청). 같은 결과를 여러 번 돌린 것처럼 세지는 않았고, 완전한 반복 실험은 아직 못 했음.

## 그래서 번역기에서는 어떻게 쓸 생각인가

이번 표본에서는 **3.8을 기본 품질 후보로 유지**하는 쪽이 타당해 보였음. 대사와 일지 문체가 대체로 자연스러웠고, 장문 출력 구조도 더 안정적이었음.

3.1 Lite도 짧은 대사·목표·아이템명에서는 쓸 만한 결과가 많았음. 비용을 줄일 후보로 남기되, 용어·태그·출력 구조 검사를 통과한 결과만 쓰고 실패한 것은 재처리하는 방향이 좋겠음.

3.8도 완벽하다는 뜻은 아님. Scholar를 ‘학사’로 좁히거나 제작비 총액을 ‘계약금’으로 옮긴 부분, 원문에 없는 ‘영원히’를 추가한 대사 등은 손볼 여지가 있었음.

Solar 두 무료 경로는 이번 결과만으로 기본 번역 모델을 바꿀 근거는 부족했음. 특히 Pro 4는 직접 API로 같은 조건에서 다시 확인해야 함.

GLM-5.3 Flash와 DeepSeek V4.1 Flash도 시도했지만, NVIDIA 무료 경로에서 GLM은 최종 응답을 받지 못했고 DeepSeek는 서비스 재시도 실패가 났음. **이 둘은 번역 품질 평가에서 제외했음. 서비스 오류를 모델 성능 점수로 처리하지 않았음.**

실제 입력·출력·추론 토큰 사용량도 웹 화면에서 전부 확인되지 않았기 때문에, 번역 1만 문장당 비용 같은 수치는 계산하지 않았음. 3.1을 저비용 후보라고 한 것은 공개 API 단가 기준임. 웹 테스트를 무료로 했다고 번역기 API 사용도 무료인 것은 아님.
