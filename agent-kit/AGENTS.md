# 툴리우스 번역기 에이전트 모드

이 폴더는 스카이림 SE 모드(플러그인 `.esp`/`.esm`/`.esl`)를 한국어로 번역하는 도구다. 사용자가 "○○ 모드 번역해 줘"라고 하면 아래 절차대로 `tullius.exe`를 써서 번역한다. 번역문은 네가(이 앱의 모델) 쓴다. `tullius.exe`는 플러그인 읽기, 태그·자리표시자 보호, 용어집·한글패치 TM·게임 사전 적용, 검증, 저장만 한다. 사용자의 GUI 번역기(툴리우스 번역기)와 같은 프로젝트·같은 규칙을 쓴다.

## 지킬 것

- 프로젝트 DB, 플러그인, `work\` 안의 `pending.json`·`responses\`를 직접 고치지 않는다. 언제나 `tullius.exe` 명령으로만 한다.
- 다른 AI API나 웹 번역을 부르지 않는다. 번역은 네가 직접 한다.
- 요청 파일(`request.md`)의 지시와 응답 형식을 그대로 따른다. 형식을 바꾸거나 설명을 덧붙이지 않는다.
- 사용자가 묻지 않으면 용어집·설정을 바꾸지 않는다.
- 번역기 앱(TulliusTranslator)이 켜져 있으면 쓰기 명령이 거부된다. 그때는 사용자에게 앱을 닫아 달라고 한다.

## 절차

1. **열기**: `.\tullius.exe open "<플러그인 경로>"`
   - 경로를 모르면 사용자에게 묻는다.
   - 출력의 `프로젝트:` 값(키)을 이후 명령에 쓴다.
   - 현지화 플러그인이라 Strings 파일을 못 찾는다고 하면 `--strings "<Strings 폴더>"`를 붙인다.
2. **첫 요청**: `.\tullius.exe next <키>`
3. **번역 반복**
   1. 출력의 `다음 요청:` 파일(`work\<키>\request.md`)을 읽는다.
   2. `request.md`의 '답하는 법'대로 답을 `work\<키>\answer.txt`에 쓴다.
      - JSON 요청이면 `{"translations":[{"id":..,"text":".."}]}` 하나만 쓴다.
      - 글 요청이면 번역문만 쓴다.
   3. `.\tullius.exe submit <키> work\<키>\answer.txt`
   4. 출력에 다음 요청이 있으면 1로 돌아간다. `번역 완료`가 나오면 4로 간다.
4. **품질검사**: `.\tullius.exe check <키>`
   - 나온 문제를 읽고, 고칠 줄을 `work\<키>\edit.json`에 `[{"order": 순번, "text": "고친 번역"}]`로 쓴다.
   - `.\tullius.exe edit <키> work\<키>\edit.json`을 실행한 뒤 다시 `check`한다.
   - 순번은 `check` 출력의 `#숫자`다.
   - 원문과 다르게 옮긴 것이 아니라 검사가 잘못 짚은 경우(예: 사람을 뜻하는 Master를 "스승"으로 옮긴 것)는 고치지 말고 보고에 적는다.
5. **저장**: `.\tullius.exe export <키>`
   - 번역된 플러그인이 `output\<키>\`에 생긴다.
6. **보고**: 사용자에게 다음을 짧게 알린다.
   - 번역한 줄 수
   - 품질검사 결과(고친 것, 남긴 것과 이유)
   - 저장 위치
   - 남은 일

## 답할 때 주의

- `__XT_...__` 보호 토큰, `<Alias=...>` 같은 태그, `[pagebreak]`, 줄바꿈은 개수와 철자를 그대로 둔다.
- 요청의 모든 id에 답한다. 빠뜨리면 그 줄만 다시 요청된다.
- 같은 요청을 다시 받으면(`알림: 같은 요청을 다시 받았습니다`) 앞의 답이 검증에 걸린 것이다. 토큰·태그·줄 수를 다시 확인하고 답한다.
- 요청의 참고 맥락(앞뒤 대사, 화자, 용어)은 말투와 어휘를 정하는 데만 쓰고, 번역문에 덧붙이지 않는다.
- 이 번역의 기준인 한글패치는 유저 번역이다. 이름·지명은 요청에 나온 용어와 TM 표기를 따른다.
- 같은 NPC의 대사는 처음부터 끝까지 한 가지 말투(존댓말/반말)를 유지한다.

## 사용량

- 요청 하나는 보통 수천 자다. 큰 모드는 구독 사용량을 많이 쓴다.
- 요청 10개마다 사용자에게 진행 상황(`.\tullius.exe status <키>`)을 한 줄로 알린다.
- 사용량 한도에 걸려 멈추면 그대로 두면 된다. 다음 대화에서 `.\tullius.exe status <키>`로 확인한다.
  - 대기 중인 요청이 있으면 그 `request.md`에 답한다.
  - 없으면 `next`로 다시 시작한다.

## 문제가 생기면

- `실패: 결과 형식이 맞지 않아 저장하지 않았습니다`: 같은 요청에 형식을 맞춰 다시 답한다.
- `알림: 번역기가 이 답이 맞는 요청을 다시 만들지 않아…`: 새로 만든 `request.md`에 답한다(사용자가 그사이 앱에서 고친 경우).
- `실패: 대기 중인 요청이 있습니다`: `next` 대신 그 요청에 답한다.
- 그 밖의 오류는 출력 그대로 사용자에게 알린다.
