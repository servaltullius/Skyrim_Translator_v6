# 일반 API 최적화 구현 — 2026-09-29

이 문서는 첫 최적화 묶음의 기록이다. 후속 호출 상한·설정 저장·책 문맥 실험과 최신 검증은 [파이프라인 개선 보고서](2026-09-29-pipeline-defaults-implementation.md)를 참고한다.

기준 커밋 `df38150`, 실행 버전 `2026.09.29-optimization`. [조사](2026-09-29-quality-cost-optimization.md)를 재검수하고 [구현 계획](../plans/2026-09-29-standard-api-optimization.md)에 따라 첫 개선 묶음을 적용했다. Batch API와 Flex는 제외하며 기존 일반 요청의 BatchSize는 유지한다.

## 재검수 판단

3.8 Flash Low를 기본으로 유지하며, 용어 전달 오류와 비용 계측을 먼저 고치는 방향이 타당하다. 자동 Lite 분담, 전수 AI 재검수, TM 키 변경, 장문 문맥 확장은 실제 앱 출력 평가를 거친 후 판단한다. 기존 세션 시드 번역은 실제 대상 행을 완료 처리하므로 불필요한 20행 중복 호출로 계산하지 않았다.

추가로 JSON 배치 프롬프트의 참고용 용어집이 `(Source, Target)` ValueTuple 그대로 직렬화되어 빈 객체로 전달되는 문제를 발견했다. 회귀 테스트가 `source` 키 누락으로 실패하는 것을 확인한 후, 번역·수리 양쪽을 명시적인 `source`/`target` 객체로 수정했다. 텍스트 프롬프트 경로에는 같은 직렬화 문제가 없었다.

## 적용한 변경

| 항목 | 이전 | 변경 후 | 검증 범위 |
|---|---|---|---|
| 참고 용어집 | JSON에서 용어 필드 누락 | 번역·수리 요청에 원문/번역 전달 | 두 프롬프트 JSON을 파싱하여 실제 값 확인 |
| 실패 응답 계측 | 결과 검증 예외가 발생하면 usage 유실 | 수신한 HTTP 상태·usage·종료 사유를 보존, 실패 로그 1회 | MAX_TOKENS/SAFETY, 단일/다중 후보, 잘못된 JSON/429 |
| 호출 진단 | 사용 목적·추론·캐시 상세 부족 | 번역/청크/수리/비용 샘플/문맥 목적 및 추론·캐시 토큰 표시 | 목적 필드가 API JSON에 전송되지 않는 것도 확인 |
| 캐시 | TM 선별 전 생성 시도 | 첫 실제 생성 요청에서 생성, 미지원 시 일반 요청, 정리 시 10초 취소 제한 | TM 100% 재사용·빈 실행은 캐시 호출 0회, 일반 실행은 생성 1회 |
| 책 모델 | 제목 선택만 가능 | 제목/본문 각각 선택, 선택한 종류에 공통 책 모델 적용 | 선택 조합과 기존 설정 로드·저장 호환성 |
| 자동 용어 | 새 학습 용어 강제 토큰 적용·활성 저장 | 실행 중 참고 힌트, 새 저장 항목은 비활성 PromptOnly 후보 | 대사 제외, 수동 용어 우선, 기존 용어 보존 |

책 본문 선택은 기본적으로 꺼져 있다. 기존 제목 설정을 본문까지 확대 해석하지 않는다. 책 전용 모델이 기본 모델과 같으면 실행을 나누지 않는다. 분리한 책 실행에는 기존 책 경로처럼 품질 승격을 덧붙이지 않으므로 선택한 책 모델 자체를 검수해야 한다.

기존에 저장한 Auto(Session) 항목도 변경하지 않았다. 새 정책은 이번 버전에서 새로 학습·저장하는 항목에 적용된다. 자동 힌트는 강제 치환보다 용어 통일성이 약할 수 있으므로, 확정 용어는 사용자 검수 후 용어집에서 관리한다.

## 남은 범위와 해석

현재 변경의 **번역 품질 개선률·전체 비용 절감률은 미측정**이다. 테스트 수와 통과율을 번역 품질 점수로 해석하지 않는다. 참고 용어가 실제로 전달되는 것과 의미 번역이 좋아지는 것은 별도 검증이다.

로그 비용은 API가 제공한 사용량과 앱 가격표에 기반한 생성 비용 추정이다. 캐시 보관료·세금·사용량 미제공 호출을 모두 포함하는 청구 명세가 아니다. HTTP 비성공 응답은 상태와 오류를 남기며 usage가 없는 비용을 0으로 만들지 않는다. 서버가 usage를 준 생성 응답을 앱이 거부하는 경우에 해당 usage를 보존한다.

요청 목적 태그를 추가했지만 run/row/chunk ID, 재시도 횟수, 품질 승격의 별도 태그, 요청 총예산은 이번에 추가하지 않았다. 캐시는 작은 작업의 손익분기점 자동 판정이나 미지원 원인별 분류까지 구현한 것이 아니다. 실제 계정의 캐시 지원·할인 효과도 아직 실측하지 않았다.

책 제목·앞뒤 청크 문맥 추가, 모델 자동 분담, 검수 등급과 REC를 포함하는 TM 스키마, 의미 오류 자동 평가와 기존 120행을 사용한 실제 앱 품질 비교는 다음 검증 대상이다. LOTD 원문 통계나 기존 웹 모델 비교를 이 버전의 품질·비용 실측치로 전용하지 않는다.
