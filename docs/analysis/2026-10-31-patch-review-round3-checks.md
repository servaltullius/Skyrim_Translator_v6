# 한글패치 3회차 검수: 번역기 검사 먼저 (2026-10-31~)

1·2회차는 사람이 읽어 고칠 줄을 찾았다. 이번에는 번역기 1.16.39의 품질 검사를 한패 본편 다섯 마스터에 돌려 후보를 뽑고, 기계로 확인하기 쉬운 것부터 덩이로 나눠 반영한다.

- 작업 폴더는 `artifacts/patch-review-r3check-20261031/`이고, 진행 상황은 `STATUS.md`에 있다.
- 사용자의 전역 DB·프로젝트는 건드리지 않았다(`--global`·`--projects`·`--work`를 작업 폴더로).

## 방법

1. **검사**: 영어 마스터를 에이전트 프로젝트로 열고(`open --strings`, 영어 strings는 `Skyrim - Interface.bsa`에서 꺼냄), 한패 strings로 채운 뒤(`korean --strings`), `check --all`을 돌린다(`run-master.sh`).
2. **모으기**: 서로 다른 줄 5,946개를 덩이 A~E로 나눴다(`collect.py`, `summary.md`).
   - A: 태그·자리표시자, 숫자, UI 조각의 앞뒤 공백, 보이지 않는 글자(약 300줄)
   - B: "<dur> 초 동안"의 띄어쓰기(323줄). 한패의 표기 규칙(`<mag> 의 피해`, `<dur> 초 동안`)과 반대라 고치지 않는 쪽을 권한다(사용자 결정 전).
   - C: 용어·이름(약 1,300줄), D: 말투(약 2,400줄), E: 끝 잘림·같은 원문 다른 번역 등(약 90줄)
3. **판단**: 하위 에이전트가 줄마다 고칠지 답하고(`a-review/`), 제안을 모두 직접 읽는다(`chunk-a-merge.py`).
4. **사본 확인**: 고친 한패 사본으로 다시 채우고 검사해, 새 경고가 없는지 본다(`compare-copy.py`).
5. **반영과 동기화**: `apply --write` 뒤 다음을 맞춘다.
   - USSEP 4판(`ussep-scan.sh`)
   - USCCCP(`usccp-check.py`)
   - TM
   - 사전(`build-dict.sh`)
   - 모드팩

- 숫자가 다른 35줄은 모두 그대로 둔다. 번역자가 실제 효과 값이나 뜻으로 옮겼다.
- "+<mag>"를 "<mag> 증가합니다"로 옮긴 11줄은 결함이 아니다.
- **반영한 것**
  - 드래곤 관련 능력 설명 2줄: 영어처럼 `<25>%`·`<10>%`(옛 글은 꺾쇠 없이 `25%`·`10%`). 같은 한국어를 가진 MGEF·PERK는 영어도 `25%`라 그대로 둔다.
  - 검은 책 메시지 상자 4줄: 메시지 상자에서는 %를 %%로 써야 보인다. 같은 책의 다른 선택지처럼 %%를 쓰거나, % 없이 영어 뜻대로 옮겼다("매지카를 소모하지 않습니다").
  - GMST UI 조각 7줄: 게임이 다른 글자와 이어 붙이는 조각이라 영어의 앞뒤 공백을 살렸다(" - 의식을 잃었습니다.", " 장비" 등).
  - 카그루메즈 일지 1줄: 보이지 않는 글자(U+200B)를 지웠다. USSEP 4판에도 같은 글이 있어 함께 고쳤다.
  - 검은 책 보상 선택지 18줄: 영어의 빈 줄(`\r\n\r\n`) 대신 줄바꿈+공백이라 번역기 태그 검사에 걸렸다. 영어처럼 빈 줄로 바꿨다(4줄은 위 %와 같은 줄).
- **뺀 것**: 콜론 앞 공백 1줄(다른 에이전트 검수에서 화면에 보이는 차이가 아니라고 봄)
- **그대로 둔 것**: USSEP 4.2.9a·4.3.8a·4.3.9c는 검은 책 3줄(마법의 탐구자, 힘의 비밀, 비전의 비밀)을 덮어쓴다. USSEP가 영어 자체를 고친 레코드라 USSEP의 자기 번역이고, 이미 `%%`·빈 줄을 갖췄다. USSEP를 쓰면 이 3줄은 USSEP 글로 보인다("지구력이 소모되지 않습니다" 등).
- **확인**
  - 반영 전 사본으로 Skyrim·Dragonborn을 다시 채우고 검사했다. 검사 결과는 같았다(새 경고 0).
  - 태그가 맞지 않아 채우지 않은 줄은 Skyrim 651→649, Dragonborn 111→93이다. 검은 책 18줄은 이제 한패 글이 그대로 채워진다.
  - "바닐라 대사·이름인데 한글패치와 다르게 옮긴 줄"은 Skyrim 582→584, Dragonborn 84→102로 늘었다. 새로 채워진 줄이 옛 사전을 담은 EXE와 달랐기 때문이다. 새 사전을 넣은 빌드로 다시 돌리면 582·83이다(Dragonborn은 카그루메즈 일지까지 맞아 하나 줄어듦). 검사 결과는 그때도 같다.
  - 실제 한패는 사본과 같다.
  - USSEP는 판마다 그 3바이트와 크기 필드 셋만 다르다. 다시 scan하면 old-patch 0이다.
  - 사전은 쓰기 전 한패로 다시 만들면 저장소 사전과 바이트까지 같다. 그래서 새 사전의 차이는 이 28줄뿐이다.

## 번역기 결함(이번에 찾음)

- `korean`이 Update.esm·Dragonborn.esm에서 정규식 시간 초과로 통째로 멈췄다. eb33957에서 고쳤다.
- 한패 줄을 채울 때 후처리가 망가뜨리거나 검사가 거부한 것(2026-10-31 고침)
  - 늘인 말: "조오오오오오오오은 날이군" → "…는 날이군". 늘인 '좋은'의 은을 조사로 봤다. 끝 두 음절이 같은 모음을 ㅇ으로 되풀이하면("오오", "으으") 은/을을 낱말 일부로 본다(품질 검사도 같은 함수). 한 번만 되풀이한 꼴은 언어·상아·생애 같은 명사라 계속 고친다.
  - 괄호 조사: "<Alias.ShortName=QuestGiver>이(가) 이 반지를" → "…이가 반지를". "(가) 이"처럼 괄호 뒤 띄어쓰기를 허용해 지시어를 먹었다. "(가)이"처럼 붙인 꼴만 본다.
  - 단위: "<30> 의 지구력 피해" → "<30>초 의". 영어에서 같은 `<30>`이 피해량과 초에 함께 쓰이면, '동안' 앞의 `<30>`에만 '초'를 붙인다.
  - 부호: "+<mag> Speechcraft"를 "화술이 <mag> 증가합니다"로 옮긴 줄을 "자리표시자 불일치"로 거부했다. 부호를 말로 옮긴 것은 받는다. '-'는 번역문에 감소·줄어·낮아 같은 말이 있을 때만 받는다. 말 없이 빠지면 증가로 읽히기 때문이다. 부호 뒤집기·없던 부호·값 빠짐은 계속 거부한다.
  - 이것을 열자 드러난 것 둘
    - 게임 사전의 줄 배치(Relayout)가 태그 경계 공백을 영어에 맞춰 "화술이<mag>", "<mag>증가합니다", "<Alias=Player> 을(를)"을 만들었다. 이제 줄바꿈만 영어를 따른다.
    - 자리표시자 보호가 "<b>2 -</b>"의 "-</b>"를 부호 붙은 자리표시자로 읽었다. 닫는 태그 앞 줄표는 부호가 아니다.
  - 확인: 다섯 마스터를 고치기 전 빌드와 고친 빌드로 채웠다(`fix-compare.py`).
    - 23줄이 달라졌다. 3줄은 망가지던 줄이 한패 글대로 돌아왔고, 20줄은 부호를 말로 옮긴 한패 줄이 새로 채워졌다.
    - 품질 검사 결과는 같다.
    - 게임 사전 경로는 짝 84,625개 가운데 206개의 최종 글이 바뀌었다. 그중 155개는 한패와 똑같아졌다. 새로 거부된 줄은 없다.
- 남은 것: 번역기는 한패의 "<dur> 초 동안"을 "<dur>초 동안"으로 붙인다(PlaceholderUnitBinder.TightenUnitSpacing). 덩이 B와 같은 표기 결정이라 사용자 결정 뒤에 정한다.
