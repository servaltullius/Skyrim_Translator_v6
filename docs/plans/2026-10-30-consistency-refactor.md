# 정합성 리팩토링 계획 (2026-10-30, 1.16.37 뒤)

번역기 전체를 다시 짜지 않는다. 결함이 되풀이해 나온 이음새만 덩이로 나눠 정리한다.

이 계획은 읽기 전용 점검 세 가지의 결과를 합친 것이다.
- 줄 상태·메모 규칙
- GUI와 에이전트 모드의 중복 흐름
- 복사되거나 한 곳에 갇힌 규칙

계획도 따로 검수를 받아 반영했다. 점검 때 앱·테스트·에이전트 명령은 실행하지 않았고, 사용자 프로젝트 56개 사본(`artifacts/lqa-compare-1.16.28/projects`)은 sqlite를 읽기 전용으로만 조회했다. 경로는 `src/XTranslatorAi.Core`를 Core, `src/XTranslatorAi.App`을 App으로 줄여 쓴다.

**규모(2026-10-30)**
- Core 3만 8천 줄, App 2만 줄, 테스트 3만 1천 줄(2,296개)

## 확인 방법 (모든 덩이 공통)

덩이마다 아래 순서로 마친다.
1. 작업
2. 다른 에이전트 검수
3. 고침
4. 전체 테스트
5. 덩이에 맞는 비교
6. 사용자에게 보고하고 다음 덩이로 넘어갈지 묻기

**비교**
- **품질 검사가 바뀌는 덩이:** 56개 사본에 `agent check --all`을 돌려 1.16.37(기준 1,229건)과 비교한다. 동작을 바꾸지 않는 덩이는 "같음"이어야 하고, 결과가 바뀌는 덩이는 바뀐 건을 한 건씩 검토한다.
- **메모와 저장 경로가 바뀌는 덩이(1·2):** `check`는 메모를 읽기만 해서 이 경로를 지나가지 않는다. 그래서 원본 플러그인이 있는 사본을 한 번 더 복사해 플러그인을 다시 열고, StringNote를 전후로 비교한다. 불변식(직접 수정 줄 + TM 메모 = 0, 건너뜀이 아닌 줄 + agent_hold = 0)도 센다.
- **전역 DB:** `agent check`는 `--projects`로 사본을 가리켜도 사용자의 실제 전역 DB를 연다(AgentCommand.cs:52). 코드상 열 때 스키마 이전, 내장 용어집 보강, 도장 파일 쓰기가 일어날 수 있다. 또 사용자가 중간에 전역 용어집이나 TM을 고치면 기준값이 흔들린다. 그래서 덩이 0에서 전역 DB 위치를 바꾸는 옵션을 열어(이미 있는 globalRootOverride), 비교를 전역 DB 사본으로 돌린다.
