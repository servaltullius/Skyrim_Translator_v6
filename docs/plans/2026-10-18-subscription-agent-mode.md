# 구독 앱으로 번역하기 (에이전트 모드) 설계안

2026-10-18 작성. 아직 구현 전이다.

## 목표

API 키 없이 **구독만으로** 툴리우스 번역기를 쓰게 한다.

- 사용자는 이미 결제한 앱에서 번역기 폴더를 연다.
  - Claude 앱(Claude Code, Pro/Max)
  - ChatGPT의 Codex(Plus 이상)
  - 구글 안티그라비티
- 그리고 "이 모드 번역해 줘"라고 말한다.
- 그 앱의 모델이 번역기의 로컬 도구를 실행하며 번역한다. 결과는 지금 API 번역과 같은 형식, 같은 검사를 거친 플러그인이다.

### 지켜야 할 원칙

1. **번역기 도구는 AI를 부르지 않는다.** 네트워크도 API 키도 쓰지 않는다. 모델이 필요한 일은 모두 사용자가 대화하는 앱의 모델이 한다.
2. **번역기가 구독 앱을 몰래 실행하지 않는다.** EXE가 `claude -p`, `codex exec`, Gemini CLI를 뒤에서 부르면 구독을 다른 프로그램이 쓰는 셈이다.
   - Anthropic은 다른 개발자가 자기 제품에 claude.ai 로그인이나 사용량을 붙이는 것을 허용하지 않는다(Agent SDK 문서).
   - Gemini CLI 약관은 다른 프로그램이 그 로그인으로 서비스에 접근하는 것을 위반으로 본다.
   - 그래서 항상 사용자가 앱에서 대화로 시키는 흐름이어야 한다.
3. **정확해야 하는 일은 도구가, 문장은 모델이 한다.** 모델마다 성향이 달라도 태그 보호, 줄 수 검증, 저장 형식은 똑같이 지켜져야 한다.

## 전체 흐름

```
사용자 ──대화──▶ 구독 앱의 모델 ──명령 실행──▶ tullius(로컬 CLI) ──▶ 프로젝트 DB
                     ▲   │                         │
                     │   └── 요청 파일 읽기 ◀──────┘ (번역할 묶음, 프롬프트)
                     └────── 번역 결과 파일 쓰기 ──▶ submit (검증·후처리·저장)
```

1. `open`: 플러그인을 가져와 프로젝트를 만든다. GUI의 "플러그인 열기"와 같다.
2. `context`: 모드 요약·용어·말투(프로젝트 맥락)를 모델이 써서 저장한다.
3. `next` → 모델 번역 → `submit`을 반복한다. 사용량 한도에 걸리면 멈추고, 다음 대화에서 "이어서"로 계속한다.
4. `check`: 품질검사를 하고, 모델이 `edit`로 고친다.
5. `export`: 번역된 플러그인을 저장하고 결과를 보고한다.

프로젝트 DB는 GUI 번역기와 같은 파일(`%LOCALAPPDATA%\XTranslatorAi\Projects\...`)이다. 에이전트로 번역한 프로젝트를 GUI에서 그대로 열어 검수할 수 있다.

## 핵심 설계: 기존 파이프라인을 "녹화·재생"으로 재사용

번역 파이프라인(`TranslationService`)은 다음을 이미 한다.

- 묶음 만들기(`TranslationBatching`)
- 태그·자리표시자 보호(`PlaceholderMasker`)
- 용어집 토큰(`GlossaryApplier`)
- 내장 TM·게임 사전·이전 번역 참조
- 대화 맥락과 화자
- 프롬프트(`TranslationPrompt`)
- 응답 해석(`TranslationResultParser`, JSON)
- 토큰 검증(`TokenValidator`)
- 후처리(`KoreanTranslationFixer`, `TranslationPostEdits`, `PromptLeakCleaner`)

이것을 다시 만들지 않고 모델 호출 지점(`IGeminiClient`)만 바꾼다.

- **녹화(`next`)**
  - `RecordingClient`로 파이프라인을 돌린다. 첫 모델 호출이 오면 그 요청(프롬프트, 대상 행 ID)을 요청 파일로 저장하고 멈춘다.
  - 행 상태는 바꾸지 않는다.
- **재생(`submit`)**
  - 같은 행으로 파이프라인을 다시 돌린다. 이번에는 `ReplayClient`가 모델 대신 사용자가 받은 번역 결과 파일을 돌려준다.
  - 파이프라인이 평소처럼 해석·검증·후처리해서 저장한다.
  - 프롬프트는 같은 입력에서 같게 만들어지므로 재생이 성립한다. 요청 파일에 프롬프트 해시를 적어 두고, 재생 때 다르면 거부한다.
- **추가 요청**
  - 검증 실패로 파이프라인이 재시도나 복구를 요청하면 `ReplayClient`가 그 요청을 다음 요청 파일로 녹화한다.
  - `submit`은 "n행 저장, m행 다시 요청"을 보고한다.
  - 처음 버전에서는 재시도를 1회로 줄이고, 후보 재순위(rerank)와 세션 용어 기억은 끈다.

장점: 품질 규칙이 GUI(API) 번역과 같고, 한쪽을 고치면 양쪽에 반영된다.

## 명령 (`tullius.exe`)

| 명령 | 하는 일 |
|---|---|
| `projects` | 프로젝트 목록과 진행률 |
| `open <플러그인 경로>` | 프로젝트 만들기(GUI와 같은 가져오기). 이미 있으면 그대로 연다 |
| `status <프로젝트>` | 남은 줄 수, 대기 중인 요청 파일, 마지막 작업 |
| `context <프로젝트> --material` | 맥락 작성 재료 출력(레코드 종류, 자주 나오는 용어, 표본). 지금 `ProjectContextScanner`가 모으는 것 |
| `context <프로젝트> --set <파일>` | 모델이 쓴 맥락 저장(GUI와 같은 형식) |
| `next <프로젝트> [--max-lines N]` | 다음 묶음 요청 파일을 만들고 경로·요약 출력 |
| `submit <프로젝트> <결과 파일>` | 검증·후처리·저장. 받은 줄, 거부한 줄과 이유, 다음 요청 |
| `lookup <용어>` | 용어집·내장 TM·게임 사전에서 표기 찾기(모델이 이름을 지어내지 않게) |
| `check <프로젝트>` | 품질검사(GUI와 같은 `LqaScanner`, 화자별 말투 포함) 결과 |
| `edit <프로젝트> <파일>` | 줄 고치기(GUI 직접 수정과 같이 "수정됨"으로 저장) |
| `export <프로젝트> [출력 폴더]` | 번역된 플러그인·Strings 저장 |

- 모든 명령은 사람이 읽는 출력과 `--json` 출력을 함께 지원한다.
- 요청·결과 파일은 프로젝트별 작업 폴더(`%LOCALAPPDATA%\XTranslatorAi\AgentWork\<프로젝트>\`)에 둔다.
- DB는 언제나 도구만 쓴다. 앱이 켜져 있으면 쓰기 명령은 거부한다(GUI와 동시 쓰기 방지).

### 요청·결과 파일

- 요청 파일(`request-0001.json`)
  - 프로젝트, 행 ID 목록, 프롬프트 해시, 프롬프트 전문(`prompt`), 응답 형식 설명
- 결과 파일(`response-0001.txt`)
  - 모델이 프롬프트가 요구한 그대로 쓴 응답(지금 API 응답과 같은 JSON)

모델은 프롬프트를 읽고 결과 파일만 쓰면 된다.

## 안내 파일

- `AGENTS.md`(본문)
  - Codex가 읽는다.
  - 안티그라비티가 읽는 파일 이름은 구현 때 확인한다.
- `CLAUDE.md`, `GEMINI.md`
  - `AGENTS.md`를 가리키는 한 줄만 둔다.

`AGENTS.md`에 적을 것:

1. **역할**: 이 폴더는 스카이림 모드 번역 도구다. 번역 요청을 받으면 아래 절차대로 `tullius.exe`를 쓴다.
2. **절차**: open → context → next/번역/submit 반복 → check/edit → export → 보고
3. **금지**
   - DB·플러그인 파일을 직접 고치지 않는다.
   - 외부 AI API를 부르지 않는다.
   - 용어집을 묻지 않고 바꾸지 않는다.
   - 프롬프트의 응답 형식을 바꾸지 않는다.
4. **번역 규칙 요약**: 자세한 내용은 프롬프트에 있다.
   - 내장 TM은 유저 번역이다.
   - 이름은 `lookup` 결과를 따른다.
   - 화자별 말투를 한 가지로 유지한다.
5. **사용량**: 한 번에 몇 묶음을 하고 진행을 알릴지, 한도에 걸렸을 때 `status`로 이어서 하는 방법
6. **보고 형식**: 번역한 줄 수, 품질검사 결과, 남은 일

## 배포

릴리스에 "에이전트 키트" zip을 따로 낸다.

```
TulliusAgentKit/
  tullius.exe        (CLI 단일 실행 파일, Core 공유)
  AGENTS.md  CLAUDE.md  GEMINI.md
  docs/agent/        (절차·규칙 상세, 문제 해결)
  사용법.txt          (앱별 폴더 여는 법, 첫 요청 예시)
```

- GUI 번역기와 같은 버전 번호로 함께 낸다. 같은 Core를 쓰므로 품질 규칙이 어긋나지 않는다.
- 사용자 안내: "구독 앱에서 이 폴더를 열고 '○○.esp 번역해 줘'라고 말하세요."

## 구현에 필요한 정리

- **기존 설치 이관 코드의 위치**
  - 프로젝트 경로(`ProjectPaths`), 내장 용어집·TM 시드(`BuiltInGlossaryService`, `BundledFranchiseTmSeedService`), 게임 사전 로드는 지금 App(WPF) 프로젝트에 있다.
  - CLI가 GUI와 같은 전역 DB를 쓰려면 이것들을 Core(또는 새 공용 라이브러리)로 옮긴다.
- **파이프라인 옵션**: `TranslateIdsRequest`에 녹화·재생에 맞는 설정 묶음을 둔다.
  - 동시성 1, 재시도 1, rerank·세션 용어 기억 끔
- **새 테스트**
  - 녹화한 요청과 재생 결과가 API 번역과 같은 행을 저장하는지
  - 프롬프트 해시가 다르면 거부하는지
  - 토큰이 깨진 응답이 다시 요청되는지
  - 테스트는 지금 `PluginDialogueScopeTests`의 가짜 클라이언트 방식으로 만든다.

## 위험과 대응

| 위험 | 대응 |
|---|---|
| 구독 사용량 한도(5시간·주간)로 큰 모드가 중간에 멈춤 | 모든 상태를 DB·작업 폴더에 남기고 `status`로 이어 하기. 안내 파일에 묶음 수 조절법 |
| 묶음마다 긴 프롬프트가 들어가 사용량을 많이 씀 | 1단계는 프롬프트 전문으로 측정. 많으면 공통 규칙을 처음 한 번만 보내는 짧은 형식을 2단계에 검토 |
| 모델이 절차를 벗어남(파일 직접 수정 등) | 쓰기는 CLI만, 앱 실행 중 거부, `submit` 검증에서 형식 오류는 저장하지 않음 |
| 모델마다 품질 차이 | 같은 프롬프트·후처리·품질검사. 앱별 시험 결과를 문서에 기록 |
| 각 회사 약관·요금제 변경 | 원칙 1·2(도구는 AI 호출 없음, 앱을 몰래 실행하지 않음)를 지키고, 배포 전 앱별 조건 재확인 |

## 단계

1. **시험판**
   - CLI에 `open`, `next`, `submit`, `export`와 녹화·재생을 넣는다.
   - Claude 앱으로 IDE Thalmor(533줄)를 번역해 사용량·시간·품질을 잰다(같은 모드의 API 번역과 비교).
2. **기능 채우기**
   - `context`, `lookup`, `check`, `edit`, `status`, 이어 하기
   - `AGENTS.md` 완성
3. **앱 넓히기**: Codex·안티그라비티에서 같은 모드로 시험하고, 안내 파일 이름·동작 차이를 반영한다.
4. **배포**: 에이전트 키트 zip, 사용법, README 안내

1단계 결과(특히 500줄당 사용량)를 보고 2단계 이후 범위를 다시 정한다.
