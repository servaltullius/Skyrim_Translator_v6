# 에이전트 모드 시험 9: MCP 도구로 번역하기 (2026-10-20)

[시험 8](2026-10-20-agent-mode-trial-codex-teldryn.md)과 Codex 조사 보고서(`artifacts/codex-research-20261020/report.md`)에서 나온 문제가 있었다.
- 셸이 한국어를 따옴표로 감싸는 방식이 앱마다 달랐다.
- PowerShell 5.1은 답 파일을 UTF-16·CP949로 썼다.
- cmd가 `&`에서 인자를 쪼갰다.

이 문제는 모두 `tullius.cmd`를 셸로 부르기 때문에 생긴다. 그래서 같은 명령을 MCP 도구로 내놓는 서버(`TulliusTranslator.exe agent mcp`)를 만들고 실제 앱에 연결했다.

- 시험 폴더: `artifacts/mcp-trial-20261020/` (Codex 출력·로그, 내보낸 플러그인, 시험 스크립트)
- 빌드: 1.16.3(d4018e8) + 이번 변경(Debug)

## 서버

- stdio, 줄마다 JSON-RPC 하나. stdout에는 프로토콜만 쓰고, 다른 출력은 stderr로 보낸다.
- 지원하는 프로토콜 판: 2025-11-25, 2025-06-18, 2025-03-26, 2024-11-05.
- 도구는 CLI 명령과 이름·인자가 같다: open, status, next, request, instructions, submit, lookup, voice, style, show, check, edit, review, korean, export, version, guide.
  - 각 도구는 그 CLI 명령을 출력을 받아 실행하므로 결과가 `tullius.cmd`와 같다.
  - 앱이 켜져 있을 때 쓰기를 거부하는 것도 같다.
- 답은 `submit`의 `answer`(문자열), 수정은 `edit`의 `edits`(배열) 인자로 받는다. 서버가 `work\.mcp\`에 UTF-8로 써서 넘긴다.
- `next`·`submit` 결과 끝에 다음 request.md 내용이 `----- 다음 요청 -----` 아래로 함께 온다.
- `lookup`은 `words` 배열로 여러 낱말을 한 번에 찾는다.
- `--work`가 없으면 번역기 옆 `agent-kit\work`를 쓴다. `tullius.cmd`와 같은 곳이다.

## 연결

| 앱 | 방법 | 결과 |
|---|---|---|
| Codex CLI 0.162.1 | agent-kit의 `.codex\config.toml`(명령 `..\TulliusTranslator.exe`, 상대 경로) | 폴더를 열면 tullius 도구가 잡힘 |
| Codex CLI | `codex mcp add tullius -- "<EXE>" agent mcp` (임시 CODEX_HOME에서 확인) | 전역 설정에 같은 항목 |

| Claude Code | `claude mcp add --scope project` | 같은 `.mcp.json` 형식 |

- Claude Code는 처음에 CLI 로그인(OAuth)이 만료돼 연결 확인만 했다. 다시 로그인한 뒤 번역까지 시험했다(아래 "Claude 시험").
- 안티그라비티·Gemini CLI는 폴더별 설정이 없어 전체 경로가 필요하다. `tullius.cmd mcp-config`가 이 번역기의 경로를 넣은 설정을 보여 준다.

## GUI 번역기와 에이전트 모드의 차이(Gemini)

요청 자체는 같다. 에이전트 모드는 GUI의 번역 실행(`TranslationRunnerService`)을 그대로 돌리고, 모델을 부르는 대신 요청을 request.md로 내보낸다.
- 시스템 프롬프트는 instructions.md로, 묶음 요청은 request.md로 나간다.
- 용어집·TM·게임 사전·이름 기억·화자 정보·태그 보호·저장 검사·다시 묻기도 같다.

| | GUI 번역기 (Gemini API) | 에이전트 모드 (안티그라비티) |
|---|---|---|
| 모델 | gemini-3.8-flash (사용자 설정 기본값) | Gemini 3.8 Flash (앱에서 고름) |
| 생각 수준 | `thinkingLevel: low` | Medium(앱 기본값) |
| 묶음 크기 | 사용자 설정 12줄 | 프로젝트 기본 30줄 |
| 위험한 줄 후보 3개 중 고르기(rerank) | 켬 | 끔 |
| 품질 상향(다른 모델로 다시) | 켬 | 끔 |
| 세션 용어 기억 | 켬 | 끔(대화가 기억) |
| 프롬프트 캐시 | 켬 | 끔(앱이 관리) |
| 스스로 확인 | 없음(요청에 답만) | lookup·show·check·edit로 찾아보고 고침 |
| 앞뒤 맥락 | 요청 하나 | 대화 전체(앞 요청·안내) |

- 같은 모델이어도 생각 수준과 묶음 크기가 다르다. GUI는 그 대신 위험한 줄에 후보 여러 개와 상향을 쓴다.
- 이번 결과로 GUI와 에이전트 모드 어느 쪽이 나은지는 말할 수 없다. 검수본은 GUI 번역 뒤 사람과 AI가 여러 번 고친 것이라, GUI의 처음 결과가 아니다.

## 대사 모드 비교: Teldryn (GUI와 에이전트 모드)

엘든림 팩은 이름과 설명뿐이라, 대사 모드로 다시 비교했다. 대상은 Extended Hireling Dialogue - Teldryn(1,028줄)이다.
- **기준(검수본)**: 사람이 번역한 모드팩 한국어판을 검수 모드로 고치고, 텔드린을 하오체로 맞춘 것(`artifacts/agent-trial-review-teldryn-20261020/output/…-8c9894ad-2`).
- **GUI**(1.16.7, gemini-3.8-flash): 이름을 바꾼 시험 복사본으로 전체를 번역했다.
- **에이전트 모드**: Codex, 안티그라비티 Gemini 3.8 Flash, 안티그라비티 Gemini 4 Argon(Pro)이 각자 갈래 1/3만 번역했다. 갈래는 대화 단위를 나누지 않는다. Claude는 이 세션과 사용량을 함께 써서 뺐다.
- 비교한 줄: 세 에이전트가 모두 번역한 갈래 줄 가운데 게임 사전이 채운 줄을 뺀 267줄. 모두 텔드린이 플레이어에게 하는 말이다.
- 줄별 표: `artifacts/mcp-trial-20261020/dialogue/teldryn-lane1.tsv`.
- 실행 중에 알게 된 것: 번역기 GUI가 켜져 있으면 에이전트 모드의 쓰기 명령이 거부된다. 그래서 GUI는 에이전트 시험이 끝난 뒤에 돌렸다.

|---|---|---|---|

예 #220 "The jester that works here. He's just not funny is he?"
- 검수본: 여기서 일하는 광대 말이오. 하나도 안 웃기지 않소?
- GUI: 여기서 일하는 광대 말인데. 전혀 웃기지 않지 않아?
- Codex: 여기서 일하는 광대 말이오. 정말 재미없지 않소?
- Flash(에이전트): 여기서 일하는 어릿광대 말입니다. 참 재미없지 않아요?
- Argon: 여기서 일하는 광대 말이오. 전혀 웃기지 않더군, 안 그렇소?

정리
- 대사에서 가장 큰 차이는 **바닐라 인물의 말투**였다.
  - 텔드린은 한글패치에서 하오체로 말한다.
  - Codex는 `voice`로 한글패치 대사를 보고 하오체로 맞췄고, Argon도 하오체를 골랐다.
  - GUI와 에이전트 모드 Flash는 그 정보 없이 각자 반말과 존댓말을 골랐다. 같은 모델(Gemini 3.8 Flash)인데도 서로 다른 말투가 나왔다.
- 세 에이전트 모두 `style`로 말투를 프로젝트에 남기지는 않았다(정한 말투 표가 비어 있음).
- 그래서 고칠 거리는 하나다: 바닐라 인물의 한글패치 말투를 요청에 자동으로 넣는 것. 게임 사전에 그 인물의 한글패치 대사가 있으면, 정한 말투가 없을 때 그것을 기본값으로 쓴다. 그러면 GUI도, `voice`를 부르지 않은 에이전트도 텔드린을 하오체로 쓴다.
- 고쳤다(4f6e965).
  - 정한 말투가 없는 바닐라 인물이 플레이어에게 하는 줄에는 화자 뒤에 "(한글패치 말투: 하오체)"를 붙인다.
  - 말투는 게임 사전에 있는 그 인물의 한글패치 대사를 품질검사의 말투 판정으로 세어 정한다. 하오체 화자는 ~지, ~군을 섞어 쓰므로, 하오체 줄이 그렇지 않은 줄의 4분의 1 이상이면 하오체로 본다.
  - 판정 예: 텔드린·시세로 하오체 / 울프릭·발그루프·에스번·나지어 하게체 / 세라나·브리뇰프·팔카스 반말 / 엘렌웬 합쇼체 / 리디아(13줄)는 대사가 적어 붙이지 않음. `voice`도 이 말투를 보여 준다.
  - 고친 Debug 빌드로 GUI 재번역(`dialogue/teldryn-lane1-gui-patchlevel.tsv`): 같은 267줄에서 하오체 0줄 → 156줄, 반말 252줄 → 94줄(대부분 하오체 화자의 ~군·~지).
    - 예 #220: "여기서 일하는 광대 말이오. 전혀 재미있지 않더군, 그렇지 않소?"
- 이름(잉그예트/잉예테 등)은 이번에도 모델마다 갈렸다. 에이전트는 `names`로 목록을 보고했다(Codex는 "새 이름 줄 없음", Flash·Argon은 목록을 표로).

  - 고침: `names` 끝에 "본문 속 새 이름 후보"를 더했다. 번역한 본문 줄의 대문자 낱말 묶음("War of Betony", "Auryen Morellus") 가운데 용어집·TM·게임 사전·번역한 이름 줄에 없는 것이다. 한국어는 붙지 않아, 에이전트가 본문에서 어떻게 옮겼는지 함께 적는다(guide-translate.md).
  - 거르는 것: 문장 첫 낱말("During the …", "But the Dwemer"), 앞의 The·My, 소유격 's, 문장 첫머리에만 나오는 한 낱말, 본문에 소문자로도 나오는 한 낱말(Order), 복수형(Dragon Priests는 Dragon Priest로 앎).
  - LotD Claude 사본: 37개. Claude가 손으로 적은 이름(오리엔 모렐루스, 베토니 전쟁, 드래곤본 갤러리, 코르토르 등)이 다 들었다. 이름 아닌 것은 Lordship, Mad God, Dual Patrons 정도였다.
  - 텔드린 대사 사본: 30개, 대부분 다른 모드 NPC 이름이고 이름 아닌 것은 Cassock, Shame Skyrim 정도였다.

## GUI가 TM 이름을 놓친 것 (2026-10-20)

LotD 블라인드 테스트에서 에이전트 셋은 `lookup`으로 한글패치 표기를 찾아 썼다. GUI는 TM에 있는 표기도 놓쳤다.

| 원문 | TM | GUI | 원인 |
|---|---|---|---|
| Fall of the Snow Prince | 눈의 왕자의 몰락 | 스노우 프린스의 몰락 | 이름 참고(`ReferenceNameIndex`)가 네 낱말까지만 이름으로 받았다 |
| Dragon Priests | 드래곤 사제(단수만 TM에 있음) | 드래곤 프리스트 | 복수형 s가 붙으면 맞추지 않았다 |

- 고침: 이름을 여섯 낱말까지(사이 of/the/and 포함) 받고, 두 낱말 이상 이름은 끝에 s가 붙은 복수형도 같은 번역으로 고정한다(한국어는 복수를 표시하지 않는다). 한 낱말 이름은 그대로 정확히 맞춘다.
- 이름 참고에 든 TM 이름이 5,913개에서 5,987개로 늘었다. 새로 들어간 것은 책 제목·아이템·장소 이름이다. 퀘스트 목표("…찾기")는 기존 한국어 끝 검사로 빠진다.
- 확인: LotD 팔머 연구·샬리도어 노트 요청에 "눈의 왕자의 몰락", "드래곤 사제"가 고정 이름으로 붙었다(GUI와 에이전트 모드가 같은 요청을 만든다).
- 남은 차이: 에이전트는 번역 뒤 품질검사로 스스로 고치고, GUI는 사람이 고친다. 모델도 다르다(GUI gemini-3.8-flash).

## 긴 책이 "추가 생성 호출 상한(8)"에 걸리던 것 (2026-10-20)

LotD 비교에서 GUI로 긴 책을 18번 번역해 2번(The Blades, Kodlak's Journal)이 이 오류로 멈췄다. 다시 번역하면 됐다.

- 재현: 벤치마크 `eval-run`으로 LotD 긴 책 8편을 세 번 번역했다(`artifacts/genlimit-20261020/runs`). 세 번째에 Kodlak's Journal이 같은 오류로 멈췄다.
- 원인: 이 책에는 플레이어 대명사 태그(`<Alias.PronounPos=Player>` his/her, `<Alias.PronounPosObj=Player>` his/her own 등)가 18개 있다. 한국어는 이런 대명사를 보통 빼고("그 기개로"), 모델도 태그를 뺐다. 그런데 검사가 빠진 토큰을 오류로 보고 다시 물었다. 줄을 잘게 나눠 다시 묻다가 상한 8번을 다 썼다.
  - 한글패치도 대명사 태그를 자주 뺀다. PronounPosObj는 13개 중 11개를 뺐고, 이 책(바닐라 Kodlak's Journal)도 뺐다. 태그를 두면 게임이 영어 대명사를 넣는다.
- 고침:
  - 대명사 별칭 태그를 `__XT_PH_PRON_####__`으로 따로 가린다.
  - 번역에서 빠지면 통과시킨다(토큰 검사, 태그 수 검사, 보호 글자 검사, 복원). 늘거나 새로 생기면 여전히 오류다. 이름 태그(`<Alias=…>`, ShortName)는 그대로 엄격하게 본다.
  - 요청 규칙에 "대상 언어가 대명사를 빼면 이 토큰도 빼도 된다"를 넣었다.
- 확인: 같은 8편을 세 번 다시 번역했다(`after2`). 실패 0번, Kodlak 요청 1~3번(전에는 최대 6번 뒤 실패), 전체 호출 20~23번(전 20~32번). Kodlak은 대명사 태그 18개를 모두 빼고 자연스럽게 옮겼다("이름은 <Alias=Player>라 하고, 벌써 패기로 서클 구성원 몇몇의 마음을 사로잡았다").
- 처음 고친 판은 복원 단계(`PlaceholderMasker.Unmask`)가 빠진 토큰을 따로 막아서 세 번 모두 실패했다(`after`). 복원도 고쳐서 위 결과가 나왔다.

## 큰 모드에서 프로젝트 문맥 생성이 잘리던 것 (E310, 2026-10-20)

- 증상: LotD를 GUI로 열고 "문맥 생성"을 누르면 `E310 GeminiException: finishReason=MAX_TOKENS (output truncated)`로 실패했다(앱 로그 2026-10-20 17:19).
- 원인: 문맥 생성 요청은 출력 한도가 4,096토큰이고, 사고(thinking) 설정이 없어 모델 기본값으로 생각했다. gemini-3.8-flash는 사고 토큰도 출력 한도에서 쓴다.
  - 같은 요청을 직접 보내 보니, 한 번은 MAX_TOKENS로 잘렸다. 다른 한 번은 사고 2,756토큰에 답 505토큰으로 겨우 들어갔다. 사고를 low로 두면 사고 토큰이 없었다.
- 고침: 번역과 같은 사고 단계(`GeminiTranslationPolicy.GetThinkingConfigForTranslation`)를 쓰고, 출력 한도를 8,192로 올렸다. 그래도 잘리면 16,384로 한 번 더 묻는다(전에는 바로 E310).
- 확인: 새 빌드 GUI에서 LotD 사본으로 문맥 생성이 성공했다("프로젝트 문맥을 갱신했습니다"). 테스트(잘린 답 뒤 다시 묻기) 추가.

## 오늘 작업 리뷰에서 고친 것 (2026-10-20)

- 끼워 넣기 위치: 블록이 바닐라 문단 집합에 있는지만 봤다. 그래서 모드가 한 문단을 빼고 다른 문단을 더해 블록 수가 같으면, 그 뒤 블록에 한글패치의 다른 문단이 들어갈 수 있었다. 이제 원문 문단이 바닐라와 같은 순서·같은 자리에 있을 때만 끼워 넣는다. 문단 수가 다르면(더하거나 뺌) 끼워 넣지 않는다. LotD 6편에서 끼워 넣어지는 책은 전과 같다(4편).
- 보호 요소 필터: 대명사 태그는 번역에서 빠져도 되게 했더니, 원문에 대명사 태그만 있는 줄이 "보호 요소 있음" 필터에서 빠졌다. 원문에 가리는 요소가 하나라도 있으면 보호 요소로 본다.
- 짧은 줄(1.16.16): 문단이 모두 같은 사본을 그대로 채울 때 40자 미만의 짧은 줄(제목, 지은이)은 비교하지 않았다. 그래서 짧은 줄만 바뀌고 줄 수가 같으면 한글패치의 옛 짧은 줄이 들어갈 수 있었다.
  - 이제 사전에 짧은 줄의 지문도 순서대로 둔다(`PS` 줄, 584편, `paragraphs` 명령이 함께 만든다). 짧은 줄까지 같아야 그대로 채운다. 다르면 참고와 끼워 넣기로 번역한다.
  - LotD 책 1,410편: 바로 채움 245편은 그대로다. 이 길로 채워지는 8편은 모두 짧은 줄까지 같다. 짧은 줄이 달라 줄 검사에서 폴백하던 5편은 이제 처음부터 참고와 함께 번역한다(폴백 211편 → 206편).

## 코드 전체 리뷰 1차(Core)에서 고친 것 (2026-10-20)

리뷰 범위는 Core의 Plugins·Data, Text, Translation이다. 높음 1건과 중간 5건을 고쳤고, 고친 것마다 테스트를 더했다. 더한 테스트는 모두 옛 코드에서 실패하는 것을 확인했다.

- (높음) `<mag>`/`<dur>` 뒤바꿈: 한국어의 보통 순서인 "<dur>초 동안 <mag>"를 뒤바뀐 것으로 보고, 바른 문장을 틀리게 바꿨다. 이제 `<mag>` 바로 뒤에 시간 낱말이 올 때만 바꾼다.
- 503(서버 과부하)을 API 키 전환 오류로 보고, 키 전환을 켜면 첫 503에서 번역 전체를 멈췄다. 이제 키를 바꿔도 소용없는 오류로 보아 연속 3번 한도에 맡긴다.
- 같은 바닐라 책이 두 레코드에 있으면, 두 번째는 첫 번째 답에서 저장되며 한글패치 문단 끼워 넣기를 건너뛰었다. 이제 두 번째에도 끼워 넣는다.
- 약어 뒤 괄호 조사: "HP이(가)"가 "HP가(가)"가 됐다. 이제 "HP가"처럼 하나로 고른다. 이/가, 을/를, 은/는, 과/와와 빗금 형태 모두 해당한다.
- 짧은 줄만 있는 블록 밀림: 긴 문단 순서만 봐서, 짧은 제목("Part Two")이 한 블록 위로 옮겨 가면 한글패치 제목("2부")이 문단 자리에 들어갔다.
  - 이제 사전에 바닐라 영어의 빈 줄 블록마다 모든 문단(짧은 줄 포함)의 지문을 둔다(`PB` 줄, 584편).
  - 같은 자리 블록이 통째로 같을 때만 끼워 넣는다.
  - 내장 사전을 `paragraphs` 명령으로 다시 만들었다. F/T/P/PS·화자 줄 113,535줄은 그대로이고 `PB` 584줄만 더해졌다.
  - `PB`가 없는 사전(전에 직접 만든 사전)은 참고만 하고 끼워 넣지 않는다. 다시 만들면 생긴다.
- 마스터 목록이 바뀐 업데이트: 따로 둔 번역과 연결한 이전 번역·이전 원문은 옛 키로 남았다. 그래서 돌아온 원문이 복원되지 않았고, 이전 번역 참고도 사라졌다. 빠진 마스터의 레코드 번역은 아예 버려졌다.
  - 이제 같은 트랜잭션에서 세 표의 키도 새 번호로 옮긴다.
  - 빠진 마스터의 번역은 옛 키로 따로 둔다.
- 낮음으로 남긴 것: 품질 승급 경로의 끼워 넣기, 한 줄짜리 절반의 시간 초과 분할, 누락 결과 채우기의 힌트, "따옴표 없이" 지시, FindSameParagraphs의 문단 순서, Data\Strings 한글패치 감지, ArtifactCleanup의 숫자 바꿈, 줄바꿈을 넘는 `\s`.
## 코드 전체 리뷰 2차(App)에서 고친 것 (2026-10-20)

리뷰 범위는 App의 Services/AgentMode, 나머지 Services, ViewModels다. 높음은 없었다. 중간 7건과 낮음 1건(프로젝트 전환 때의 멈춤 처리)을 테스트와 함께 고쳤다. 더한 테스트는 모두 옛 코드에서 실패하는 것을 확인했다. 단, edit의 text 검사는 새로 만든 함수라 옛 코드에서 돌려 볼 수 없었다.

- 갈래(lane) 실행이 다른 갈래의 "번역 중" 줄까지 대기로 되돌렸다. 그러면 그 갈래의 분할 단계가 그 줄들을 빼서, 답이 다시 만든 요청과 맞지 않았다. 이제 자기 갈래 줄만 되돌린다.
- 오류로 끝난 줄은 다음 실행에서 같은 요청이 되어, 저장된 옛 답을 다시 받아 또 거절됐다. 그래서 `next`가 새 요청을 만들지 못했다. 이제 물을 것이 없는데 오류 줄이 남으면, 그 실행이 쓴 답을 지워 다음 `next`가 새로 묻게 한다.
- MCP 서버가 답과 수정 파일을 고정 이름(`.mcp/answer.txt`, `edit.json`)으로 썼다. 같은 작업 폴더를 쓰는 갈래끼리 서로 덮어쓸 수 있었다. 이제 호출마다 다른 이름으로 쓰고, 끝나면 지운다.
- `edit` 항목에 `text`가 없으면(키 이름이 틀린 경우) 줄을 빈 번역의 수정됨으로 저장했다. 내보내기에서는 게임 속 이름이 비었다. 이제 그런 항목이 있으면 아무것도 저장하지 않는다.
- 전역 DB 기록(기본 용어집을 넣었음, 내장 TM을 넣었음)이 DB 밖 파일이었다.
  - 망가진 전역 DB를 지우면 새 빈 DB가 기본 용어집과 시리즈 TM 없이 남았다. 이제 DB를 새로 만들 때 지난 기록 파일을 지운다.
  - TM 기록은 tm-import에서 DB 옆으로 옮겼다. tm-import를 비워도 시드 전체를 다시 넣어 사용자가 고친 줄을 덮지 않는다. 옛 위치의 기록은 처음 확인할 때 옮긴다.
- "다시 번역"이 DB의 "원문 오류 수정"·"확인함" 표시를 지우면서 화면의 표시는 남겼다. 그래서 다음 품질검사도 그 줄을 건너뛰었다. 이제 화면에서도 지운다.
- 입력 파일 옆에 `번역용어집 신규.md`가 있으면, 용어집 가져오기(전체 용어집 포함)가 파일 창 없이 그 파일을 가져왔다. 이제 늘 파일 창을 열고, 그 파일을 기본 이름으로 채운다.
- 프로젝트 전환 때 멈추는 중 끝난 작업이 오류(예: 네트워크)를 내면, 멈춤 처리가 그 오류를 다시 던졌다. 그러면 XML 열기가 열린 프로젝트만 닫고 새 파일은 열지 않았다. 이제 오류는 기록만 하고 계속한다.
- 낮음으로 남긴 것
  - MCP 서버가 호출마다 전역 DB 연결을 새로 열고 닫지 않음
  - 검수 모드가 영어가 바뀐 줄도 채움
  - `lanes.json` 동시 쓰기
  - 잘못된 MCP 메시지가 서버를 멈춤
  - 전역 DB 일부를 못 읽으면 조용히 빼고 번역
  - XML 첫 열기 실패 때 빈 DB가 남음
  - DPAPI로 풀지 못한 키가 다음 저장에서 사라짐
  - TM 파일 한 칸 오류가 파일 전체를 막음
  - 번역 중에 품질검사를 시작할 수 있음
  - 손으로 고친 줄의 TM 표시가 다시 나타남
  - 진행률이 건너뜀 줄을 세지 않음
