# 일반 API 최적화 — 재검수 및 구현 계획

사용자 요청: Batch API/Flex를 제외한 방법을 재검수한 뒤 구현한다.

## 재검수 판단

기반 개선 방향은 타당하다. 다만 품질 실험 전 Lite 자동 분담, 전수 AI 재검수, TM 스키마 이전, 문맥 대폭 확장은 도입하지 않는다. 기존 세션 시드 번역은 실제 대상 행을 처리하므로 이중 번역으로 간주하지 않는다. 캐시를 사용할 수 없는 경우에도 일반 번역은 동작해야 한다.

추가 발견: JSON 프롬프트에서 참고용 용어집 ValueTuple을 그대로 직렬화한다. 필드 직렬화를 켜지 않은 설정에서 용어가 빈 객체가 될 수 있으므로 실제 JSON 내용 회귀 테스트를 먼저 추가한다.

## 구현 및 검증

- [x] 참고용 용어집을 명시적인 source/target 객체로 전달하고 수리 프롬프트도 점검
- [x] 거부된 응답의 사용량·HTTP 상태·종료 사유를 기록하고 호출 목적/추론·캐시 사용량을 표시
- [x] 실제 생성 요청까지 캐시 생성을 늦추고 정리 시간 제한 적용
- [x] 기존 책 제목 설정을 보존하면서 BOOK:DESC 본문 적용 여부를 별도로 선택·저장; 선택한 종류는 공통 책 모델 사용
- [x] 자동 학습 용어는 실행 중 참고 힌트, 새 저장 항목은 비활성 검수 후보로 보존; 기존 사용자 용어는 보존
- [x] 관련 회귀 테스트 및 전체 테스트, 단일 파일 빌드
- [x] 재검수 결과·구현 범위·미측정 효과 문서화
- [ ] 실행 파일 백업·갱신 및 시작 확인: 자동 승인 검토가 해당 명령을 차단하여 미실행. 구체적인 사유는 반환되지 않음. 기존 루트 파일 유지, 별도 candidate 제공

API 키나 사용자 DB는 조회하지 않는다. 실제 번역/유료 API 호출 없이 HTTP fixture와 임시 DB로 검증한다. 테스트 통과를 번역 품질 개선률이나 비용 절감률로 표현하지 않는다.

결과: 496개 테스트 통과, 단일 EXE 66,499,567바이트. [구현 보고서](../analysis/2026-09-29-standard-api-implementation.md)에 산출물 경로와 SHA-256, 미완료된 시작 확인을 기록했다. 이번 소스 변경은 아직 커밋하지 않았다.
