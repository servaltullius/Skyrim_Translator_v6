## 사용 순서

1. 고급 설정의 **ESP 불러오기 설정**에서 Skyrim SE/AE, 원본 언어 슬롯, 번역 언어와 인코딩을 선택한다. 다음 `ESP 열기`부터 적용된다.
2. **ESP 열기**에서 `.esp`, `.esm`, `.esl`을 연다. ESL 플래그가 설정된 ESP도 같은 경로다. XML 추출은 필요 없다.
3. 기존 용어집, 문맥, 비용 추정, `번역 시작`, 검수 기능으로 번역한다. API 호출에는 기존 요금·할당량이 적용된다.
4. **ESP 저장**에서 아직 존재하지 않는 **새 출력 폴더 이름**을 지정한다. 그 폴더 안에 원본과 같은 플러그인 파일명 및 필요한 `Strings`가 함께 생성된다.
5. 출력 폴더 전체를 별도 MO2 모드로 설치하고, 대상 원본 모드보다 우선하도록 배치한다. 원본 모드는 메시·텍스처·스크립트 등 자산을 제공하므로 함께 유지한다. 복사한 테스트 프로필에서 확인한다.

출력물은 원본 플러그인의 번역된 대체 파일이다. 별도 FormID를 가진 패치가 아니므로 **파일명을 바꾸지 않는다**. 이 앱이 MO2 설치·활성화·원본 덮어쓰기를 수행하지는 않는다.

읽기·저장 작업은 백그라운드에서 수행하며, 하단 상태 표시줄의 **ESP 읽기/저장 취소**로 중단할 수 있다. 이때 상단 설정과 편집 탭은 잠기지만 취소 버튼은 계속 사용할 수 있다. 가져오기 DB 확정 직후의 늦은 취소는 확정한 새 프로젝트를 유지하고 나머지 보조 새로고침을 생략한다.

## 문자열과 인코딩

| 설정 | 기본값 | 대상 |
| --- | --- | --- |
| 원본 언어 | `english` | `_english.STRINGS` 같은 파일명 슬롯 |
| 번역 언어 | `korean` | 번역 요청의 대상 언어 |
| 원문 인코딩 | `utf-8` | inline 표시문구와 3종 문자열 테이블 |
| 식별자 인코딩 | `windows-1252` | EDID·MAST 읽기. 저장할 때 원본 바이트 유지 |
| 저장 인코딩 | `utf-8` | 번역본의 표시문구·문자열 테이블 |

영문 플러그인은 대부분 `windows-1252`로 저장되어 있다. 원문 인코딩이 `utf-8`인데 UTF-8로 읽을 수 없는 글자(예: `cliché`의 é)가 있으면 파일 전체를 `windows-1252`로 다시 읽고, 상태 표시줄에 "원문이 UTF-8이 아니어서 windows-1252로 읽었습니다"를 표시한다. 프로젝트도 실제로 읽은 인코딩 기준으로 만든다. UTF-8로 올바른 글자와 섞인 파일은 어느 쪽으로 읽어도 일부가 깨지므로 자동 전환하지 않고 오류를 낸다. CP949 한글 파일은 `ks_c_5601-1987`로 지정하고 다시 연다. 대체문자로 읽기 실패를 숨기지 않는다. 기술 식별자에 UTF-8/CP949를 사용한 특수 파일만 식별자 인코딩도 변경한다.

지역화 플러그인은 지정한 `Strings` 폴더 또는 플러그인 옆 `Strings`를 먼저 사용한다. 없으면 플러그인과 같은 이름의 BSA 및 `이름 - *.bsa`에서 찾는다. BSA 104/zlib와 105/LZ4를 읽는다. 같은 문자열 파일이 여러 BSA에서 서로 다른 내용으로 나오면 경로 선택을 요구한다. 이때 원하는 문자열을 별도 `Strings` 폴더로 준비하여 지정할 수 있다. 실제 테이블 출처는 프로젝트 메타데이터에 저장한다.

영어 슬롯을 사용하는 게임에서 한글을 표시하려면 내용만 한국어인 `_english.*STRINGS`가 필요하므로, 저장할 때 원본 언어 슬롯을 유지한다. `_korean`으로 자동 개명하지 않는다. 공유 StringID를 가진 여러 행의 번역이 다르면 저장을 막고 해당 ID와 관련 행을 알려준다. Search에 오류 메시지의 `string:STRINGS/42` 같은 검색어를 넣고 Status를 `(All)`로 설정한 뒤, 공유 행들의 번역을 일치시킨다. 다른 필터도 해제하면 모든 공유 행을 확인할 수 있다.

선택한 문구의 Source 위와 행 툴팁에 FormID·필드·StringID가 표시된다. `form:01000800`은 정확한 FormID, `row:12`는 행 번호로 검색한다. **보호 요소 불일치만** 필터는 저장 시 검사와 같은 기준으로 태그·페이지 구분·printf·중괄호·줄바꿈 등의 훼손을 찾는다.

## 이전 번역 참고

같은 플러그인의 이전 번역판(예: 모드 업데이트 전의 한글판 ESP)이 있으면 **프로젝트 문맥** 탭의 `이전 번역 불러오기`로 연결한다. 같은 FormID·필드끼리 짝지어, 번역할 때 그 행의 이전 번역을 참고 자료로 함께 보낸다. 모델은 지금 원문에 맞는 범위에서 기존 이름·용어(예: 시산혈해, 참격)를 따르고, 이전 번역의 조사 오류나 미번역은 따라 하지 않는다. 이전 번역을 그대로 복사하지는 않는다.

- 번역판은 저장 인코딩으로 읽고, 문자열은 그 파일 옆 `Strings`나 BSA에서 찾는다. 마스터 구성이 같아야 FormID가 맞는다.
- 연결은 필드 키로 저장되므로 ESP를 다시 열어도 유지된다. `연결 해제`로 지운다.
- 이미 번역된 행에 반영하려면 문자열 탭의 `다시 번역`으로 대기 상태로 되돌린 뒤 번역한다.
- 긴 책을 조각으로 나눠 번역할 때는 붙이지 않는다. 참고 문장은 입력 토큰을 늘린다(실측 약 38%).

## 대화 문맥과 TM

직접 입력의 INFO/DIAL 대화는 플러그인의 부모 topic FormID를 문맥 범위로 사용한다. 부모 DIAL 레코드 자체가 없는 패치도 GRUP type 7의 정보로 처리한다. 부모 근거가 없으면 같은 record 안으로 범위를 제한한다. 문맥 옵션을 꺼도 서로 다른 topic의 같은 원문을 하나의 번역으로 합치지 않는다.

기존 원문 전용 TM에는 대화의 topic 출처가 없으므로 직접 플러그인의 INFO/DIAL에는 자동 적용하지 않는다. Compare도 이 규칙을 따른다. 완료·수동 편집 번역의 재열기 복원과 동일 문맥의 실행 중 중복 재사용은 유지하며, 기존 TM 데이터는 삭제하지 않는다. 아이템 등 다른 필드 및 XML의 TM 정책은 그대로다. 따라서 직접 대화 번역은 기존 TM 적용률을 가정한 비용보다 높아질 수 있다. 비용 추정은 TM 할인 없이 각 대상 행을 포함하지만 문맥·재시도 등 모든 실제 요청을 완전히 모사하지는 않는다.

## 보존·오류 처리

- 원본은 읽기만 한다. 읽은 뒤 원본 ESP나 사용한 문자열/BSA가 변경되면 저장을 중단한다.
- FormID, 마스터 목록, 플래그, 레코드 순서 및 비번역 데이터는 유지한다. 수정하지 않은 레코드는 압축 바이트까지 그대로 복사한다.
- 번역한 레코드와 상위 그룹의 길이를 갱신한다. 지역화 플러그인은 기존 문자열 ID와 미사용 문자열도 유지한다.
- 출력 전체를 임시 폴더에 쓰고 구조·내용·디스크 바이트를 검증한 뒤 새 폴더로 확정한다. 기존 출력 폴더는 덮어쓰지 않는다.
- 미완료·건너뛴 행은 원문을 유지한다. 의도적으로 비워 둔 수동 편집은 DB에 남지만, 필수 표시문구의 빈 번역은 플러그인 저장 시 오류로 표시한다.
- 같은 입력 경로·게임·언어·인코딩·문자열 위치로 다시 열면 필드 식별자와 원문이 일치하는 완료·편집 번역을 복원한다. XML 프로젝트 DB와는 분리된다.

## 지원 범위와 검증 상태

직접 입력은 **Skyrim SE/AE**를 대상으로 한다. Fallout/Starfield는 기존 XML 경로를 사용한다. Skyrim LE/VR, 임의의 미래 확장 형식까지 검증한 것으로 해석하지 않는다.

이름, 설명, 책, 대사, 퀘스트, 메시지 및 조건부 표시문구를 지원한다. PEX/VMAD 스크립트 내용, MCM 외부 자산, 기술 식별자와 경로는 번역 대상이 아니다. 도구별 해석이 다른 일부 필드는 직접 번역하지 않고 필드 바이트를 유지하며 진단을 제공한다. 다만 지역화 파일에서 다른 번역 항목과 문자열 ID를 공유하면 참조 내용은 함께 바뀔 수 있다. 이는 필드의 의미까지 그대로 유지한다는 보장이 아니다. [필드 정의 전수 대조](analysis/2026-09-29-plugin-field-registry.md)에 구체 범위를 기록했다.

수정본은 전체 자동 테스트 **799/799**를 통과했다. 취소 버튼 접근성, 읽기·SQLite 조회 중 UI 스레드의 취소 처리, DB 확정 후 취소, 수동 편집 후 진행 숫자 갱신과 저장 실패 회귀를 포함한다. USSEP의 표시문구 **18,870개 전체**를 수정한 출력물을 xEdit 4.1.5f로 다시 읽어 기대 번역과 전수 대조했다. 누락·불일치·경계 해석 오류는 0건이며, 문제였던 `bPerkShieldCharge` 기술 변수는 원본과 같았다. 이전 후보의 변수 변경은 같은 대조 도구가 실패로 검출했다. 구조 검사만으로는 이 오류를 찾지 못했다.

USSEP 무편집 출력은 원본 SHA256과 같았다. BSA 기반 Stendarr ESL은 이름 `스텐다르의 망치`를 저장해 xEdit에서 읽었으며 플러그인 바이트는 원본과 같다. Skyrim 본체 ESM은 기술 변수 3개를 제외한 **67,388개** 표시문구를 읽고 무편집 저장했으며, ESM과 문자열 테이블 3종 모두 원본 SHA256과 같다. 자세한 기록은 [검증 보고서](analysis/2026-09-29-direct-plugin-validation.md)에 있다.

앱을 참조하지 않는 Mutagen 독립 reader로도 USSEP의 57,205개 레코드를 순회했다. 비어 있지 않은 translated getter **18,870개와 앱 목록이 모두 일치**했고 양방향 차이는 0개였다. 이는 해당 USSEP 입력의 번역 문자열 목록 대조이며, 모든 plain 문자열의 표시 여부나 모든 모드의 지원을 증명하지는 않는다.

Skyrim.esm에서는 **67,388개 문구를 모두 시험용으로 수정**한 뒤 원문과 수정문을 독립 파서로 대조했다. 앱이 노출한 항목은 모두 일치했고, ESM 바이트·테이블 ID·미편집 26개 항목도 보존됐다. 외부 파서 자체는 CPTH 조건 getter 4건과 SNDR 조회 5건의 진단을 남겨 전체 성공으로 처리하지 않았다. 범위를 명시한 별도 대조 결과다.

이 검증에서 Mutagen으로 해석한 SNDR 값 54개가 함께 바뀐 것으로 보였다. 후속 [SNDR:FNAM 확인](analysis/2026-09-30-sndr-fnam.md)에서 이 필드가 문자열 ID가 아니라 반복 재생 등의 **비트 플래그**임을 확인했다. FNAM 바이트는 그대로 유지되므로 게임 동작에 영향이 없다. 앱은 이 필드에 대한 경고를 더 이상 표시하지 않는다.

사용자 요청으로 실제 모드 검증을 LOTD에서 엘든림으로 변경했다. 본체 985개·전회 2,852개 문자열 읽기와 무편집 SHA 보존, 실제 앱 화면에서 한글 수동 편집·저장·작업 복원, 전회 원문/수정본의 xEdit 2,852개 전수 대조를 확인했다. Mutagen 문구 대조도 일치했지만 원본 PERK 효과 해석 진단은 남겨 전체 reader 성공으로 표현하지 않는다. [엘든림 검증 기록](analysis/2026-09-30-eldenrim-validation.md)에 범위를 기록했다.

이는 모든 모드의 정상 동작을 보증하지 않는다. 게임 내 표시·동작 확인은 사용자가 직접 담당하며, 그 확인을 기다려야 번역기를 사용할 수 있는 것은 아니다. 세부 로그와 원본/출력 해시는 `artifacts/direct-plugin-20260929`에 보관한다.
